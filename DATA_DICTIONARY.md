## 1. Reading conventions

These hold for every table and are not repeated in each one.

| Convention | What it means | Where it is defined |
| --- | --- | --- |
| `id` `VARCHAR(32)` primary key | A 26-character Crockford base-32 ULID: 48 bits of millisecond timestamp then 80 bits of randomness. Lexicographic order is creation order, so `ORDER BY id` is a valid proxy for time without an extra index, and B-tree inserts stay append-only. | `trs/db/base.py::new_id`, `IdMixin` |
| `created_at` / `updated_at` | Present wherever `TimestampMixin` is mixed in. Absent from append-only tables (`audit_event`, `raw_record`, `entity_resolution_decision`, `evidence_field_provenance`, `connector_run`) because those rows are never updated. | `trs/db/base.py::TimestampMixin` |
| `is_synthetic` / `synthetic_note` | Present wherever `SyntheticFlagMixin` is mixed in. Indexed. Propagates into feature snapshots, model artifacts and scores; the interface refuses to present a score as validated when any contributing record carries it. | `trs/db/base.py::SyntheticFlagMixin` |
| `JSONVariant` | Compiles to `JSONB` on PostgreSQL and portable `JSON` (TEXT-backed) on SQLite. One model definition, two engines. | `trs/db/base.py::JSONVariant` |
| `UTCDateTime` | Timezone-aware UTC, always. Writing a naive datetime raises `ValueError` at bind time rather than being silently accepted, because SQLite would hand it back naive and break every `available_at` comparison downstream. | `trs/db/base.py::UTCDateTime` |
| Controlled-vocabulary columns | Stored as plain `VARCHAR`, never as a database `ENUM` type. Validation happens in Pydantic and in application code. The cost is that the database will accept a typo; the benefit is that adding a vocabulary term needs no migration on either engine. Each such column's source enum is named in a `#:` comment on the model attribute. | `trs/ontology/enums.py` |
| Alias tables | `target_alias`, `compound_alias`, `sponsor_alias`, `indication_alias` and `program_alias` share `AliasMixin`: `alias`, `alias_normalised` (indexed, case/punctuation-folded, used for blocking), `alias_type`, `match_method` (`EntityMatchMethod`), `match_confidence`, `source_id`, `available_at`, `is_primary`. Each has a unique constraint on `(parent_id, alias_normalised)`. | `trs/db/models/core.py::AliasMixin` |
| Constraint naming | Deterministic, via a `MetaData` naming convention, so Alembic autogenerate is stable and migrations can drop constraints by name on both engines. | `trs/db/base.py::NAMING_CONVENTION` |

## 2. `available_at`: the temporal-integrity contract

Read this before any other section. It is the single property on which every reported performance
number depends.

### The definition

`available_at` is **the earliest date on which a diligent analyst could have known this fact.** It is
not the date of the underlying experiment, and it is not always the publication date.

- A 2015 paper reporting a 2011 experiment became *knowable* in 2015. `available_at = 2015`,
  `observed_on = 2011`.
- A trial registered in 2013 whose "why stopped" field was populated in 2018 yields two facts with
  two different availability dates, and they must not share a row's date.
- A target assessment is re-asserted as knowledge accumulates. Each assertion gets its own row and
  its own `available_at`; the feature layer takes the latest one *at or before* the cutoff, never
  the newest overall.

### The rule

For a development track scored at cutoff `T`, the feature vector must be a function only of rows
with `available_at <= T`. Nothing enforces this at the database level. It is enforced in exactly one
place in the code — `trs/features/temporal.py::AsOfContext` — and `trs/features/builder.py` takes an
`AsOfContext`, not a `Session`, so a call site cannot reach evidence any other way. `AsOfContext`
additionally re-verifies the rows it returns in `strict` mode (the default) rather than trusting the
SQL to have been written correctly, and raises `TemporalIntegrityError` if a row slips through.

### `as_of_date` is the other half

Where `available_at` dates a *fact*, `as_of_date` dates a *question*. It appears on `cohort_entry`,
`feature_snapshot`, `score_record` and `comparator_link`, and it is the `T` in the rule above. The
cohort's `as_of_rule` (`ind_or_cta_on` for the demonstration cohort) says which milestone on
`program_indication` supplies it.

### Where the columns are

| Table | Column | Nullability | Index |
| --- | --- | --- | --- |
| `cohort_entry` | `as_of_date` | not null | indexed |
| `comparator_link` | `as_of_date` | not null | — |
| `compound_alias` | `available_at` | **nullable** | — |
| `evidence_item` | `available_at` | not null | indexed |
| `feature_snapshot` | `as_of_date` | not null | indexed |
| `indication_alias` | `available_at` | **nullable** | — |
| `pkpd_bridge` | `available_at` | not null | indexed |
| `program_alias` | `available_at` | **nullable** | — |
| `program_biomarker` | `available_at` | not null | indexed |
| `program_target` | `available_at` | **nullable** | — |
| `safety_finding` | `available_at` | not null | indexed |
| `score_record` | `as_of_date` | not null | — |
| `sponsor_alias` | `available_at` | **nullable** | — |
| `target_alias` | `available_at` | **nullable** | — |

The nullable ones are all alias tables plus `program_target`. That is a real gap and it is recorded
in [§8](#8-known-gaps-in-the-schema): an alias with a null `available_at` cannot be temporally
filtered, and `AsOfContext` has no accessor for alias rows at all. It does not affect the current
feature set — no declared feature reads an alias — but it would matter the moment entity resolution
becomes time-aware.

Two evidence-bearing tables have **no** `available_at`: `source` (which has `published_on` and
`retrieved_at` instead) and `trial` (which has `first_posted_on` and `last_update_on`). Evidence
derived from them carries its own `available_at` on `evidence_item`, which is the column the
temporal layer actually reads.

## 4. Controlled vocabularies

38 `StrEnum` vocabularies, 365 values total, all in `trs/ontology/enums.py`.

Three conventions apply throughout:

1. **Values are stable identifiers.** They are persisted in the database and embedded in model
   artifacts. Renaming one is a breaking change requiring a feature-schema version bump and a
   migration.
2. **`unknown` means "we do not know".** It is not a negative finding, and the feature layer keeps
   the two apart — see `MissingnessReason` below and `trs/features/spec.py::ordinal()`.
3. **Ordering in the class body is conceptual, never weight.** Where an ordering is used numerically
   it is via an explicit map in `trs/features/spec.py`, restated in [§7](#7-derived-encodings).

### `MissingnessReason`

7 values.

Why a field has no value. Distinguishing these is load-bearing.

```
not_reported
not_applicable
not_yet_available
not_extracted
source_inaccessible
conflicting_sources

```

**The most load-bearing vocabulary in the schema.** Four of its seven values look similar and are not:

- `not_reported` — the study exists and is silent on this field. This is *informative*: silence about randomisation or blinding is itself a study-quality signal, and the feature layer lets the model learn an effect of not knowing via the `__missing` indicator columns.
- `not_applicable` — the question does not arise (immune competence of a cell-free assay). This is *not* informative and must never be read as a negative finding or imputed as a low value.
- `not_yet_available` — the information exists, but it postdates the as-of cutoff and was withheld to preserve temporal integrity. This is the only missingness reason that is an artefact of *our* method rather than of the world, and conflating it with `not_reported` would make the evidence base look permanently sparser than it is.
- `not_extracted` — we have the source and have not yet read this field. A backlog marker, not a finding.

`source_inaccessible` and `conflicting_sources` cover the remaining honest failures, and `present` exists so that a snapshot's missingness map is *complete* rather than implied by absence. The distinction is enforced downstream by `trs/features/spec.py::ordinal()`, which maps an unknown or not-assessed categorical to `None` and never to `0.0` — encoding ignorance as the lowest level is the commonest way an evidence-scoring system silently penalises programs for thin documentation.

## 5. Endpoint definitions

`trs/cohort/outcomes.py` declares 6 endpoints. Each is fully declarative: which
observed outcomes count as positive, which count as negative, which are excluded outright, and how
much follow-up a negative requires before it is credible. Exclusions are counted and reported — a
cohort that discards 27% of its candidates is telling you something, and the Methods page shows that
number.

The primary endpoint is **cause-specific**. A program discontinued for toxicity never got the
opportunity to demonstrate efficacy, so it is neither a positive nor a negative example for the
efficacy question and is removed as a competing event.

| Column | Meaning |
| --- | --- |
| **Kind** | `numeric`, `ordinal`, `binary`, `nominal` (expanded to one-hot columns) or `count` (non-negative integer). |
| **Transform** | Applied before standardisation. `log1p` for counts; `log2` for ratios; `logit` for proportions. |
| **Missing policy** | `impute_with_indicator` — fill with the training median/mode *and* add a `{name}__missing` column, so the model can learn an effect of not knowing. `impute_only` — fill, no indicator, used where the missing rate is so extreme the indicator would be degenerate. `zero_is_absence` — missing genuinely means zero, used only where the evidence sweep is exhaustive by construction. `explicit_level` — for nominal features, `unknown` is a legitimate level with its own column. |
| **Expected direction** | The prior belief about the association with *failure*. **Recorded but never enforced.** It is used only to flag sign-discordant coefficients in the validation report for human review. A model that silently enforces the analyst's priors cannot surprise the analyst, and surprising the analyst is the point. |
| **Scen.** | Whether a user may vary this in scenario analysis. 26 of 63 features are adjustable; the rest are excluded because no amount of work by the team could change them (the historical failure rate on the target, the indication's unmet need). |
| **Wt** | Weight in the completeness score, so "80% complete" means "80% of the evidence that actually moves this estimate is present" rather than "80% of columns are non-null". |
| **Derivation** | What evidence produces the value. The derivation *is* the scientific claim. |

An indicator column is emitted only when the training missing rate lies inside
`INDICATOR_RATE_BAND = (0.02, 0.98)`;
outside that band the indicator is near-constant and buys nothing but a penalised coefficient. The
band is recorded in the artifact so the decision is auditable rather than emergent.

## 7. Derived encodings

### Ordinal maps

Mapping an ordered category to an integer asserts equal spacing between adjacent levels. At the
sample sizes realistic for translational cohorts — hundreds, not millions — that assumption buys a
large variance reduction over one-hot coding, and it is the right trade. It is still a trade, and
each map states the scale it encodes. Where the spacing assumption is not defensible (modality,
target class) the feature is nominal and one-hot encoded instead.

## 8. Known gaps in the schema

Stated here rather than discovered later.

| Gap | Consequence | Where |
| --- | --- | --- |
| `available_at` is nullable on all five alias tables and on `program_target`. | An alias with a null availability date cannot be temporally filtered. No declared feature currently reads an alias, so nothing is presently wrong — but time-aware entity resolution would need this tightened first. | `trs/db/models/core.py::AliasMixin` |
| `AsOfContext` has no accessor for alias tables, `trial`, or `source`. | The temporal chokepoint covers `evidence_item`, `pkpd_bridge`, `target_assessment`, `program_biomarker` and `safety_finding`. Anything reading the other tables must apply its own filter, and nothing structurally stops it from forgetting. | `trs/features/temporal.py` |
| Controlled vocabularies are `VARCHAR` with no `CHECK` constraint. | The database will accept `"in_vivo"` where `"animal_in_vivo"` was meant. This is a deliberate portability trade (see [ARCHITECTURE.md](ARCHITECTURE.md) ADR-004), but it moves the guarantee entirely into application code. | `trs/db/base.py` module docstring |
| `entity_resolution_decision` has no foreign keys. | `canonical_id` is a bare `VARCHAR(32)` because the row can refer to any entity type. Referential integrity for this table is not enforced by the database. | `trs/db/models/core.py::EntityResolutionDecision` |
